# ABA Content Taxonomy And Semantic Visual Language

Last updated: 2026-06-29

Purpose:
- classify the actual content types across the ABA prototype
- define how different kinds of content should be treated visually and structurally
- guide deeper design work across the public site, Explorer, membership, tracker, and workspaces

## 1. Core content families across the ABA ecosystem

The current prototype is not one website with one content type.

It is a connected system containing several different content families:

1. Public narrative content
2. Pathway and decision content
3. Structured knowledge content
4. Application and intake content
5. Review and workflow content
6. Status, evidence, and intelligence content
7. Export and packet content

The design language should make these feel related, but not identical.

## 2. Public narrative content

### What it includes

- Home
- About
- higher-level alliance framing
- public positioning copy
- value proposition and mission content

### User mindset

- orienting
- evaluating credibility
- deciding whether ABA is relevant

### Visual treatment

This content should feel:
- editorial
- legible
- confident
- public-facing

Preferred traits:
- stronger hero statements
- calmer sectioning
- broader spacing rhythm
- fewer dense controls
- more atmospheric or symbolic visual support

This is where typography and narrative hierarchy matter most.

## 3. Pathway and decision content

### What it includes

- route chooser sections on Home
- Membership route comparison
- Tracker route overview
- Workspace gateway
- Explorer “start with” entry choices

### User mindset

- deciding where to go
- comparing entry paths
- choosing a role or intent

### Visual treatment

This content should feel:
- structured
- scannable
- directional
- action-oriented

Preferred traits:
- clear route cards
- obvious CTA hierarchy
- distinct semantic labeling
- visible differences between routes without making them look like unrelated products

These surfaces are the main wayfinding layer of the ecosystem.

## 4. Structured knowledge content

### What it includes

- Explorer landing page
- crop/problem/product views
- evidence library
- standards and regulations
- resource library
- product detail pages

### User mindset

- exploring
- comparing
- learning
- validating

### Visual treatment

This content should feel:
- information-rich
- credible
- browseable
- layered

Preferred traits:
- clearer semantic grouping of record types
- strong filtering/search hierarchy
- visual coding for content categories
- support for drill-down from summary to depth

This area wants the richest semantic iconography and classification language.

## 5. Application and intake content

### What it includes

- Membership applications
- tracker intake form
- consent and eligibility capture
- product-registration submission fields

### User mindset

- focused
- cautious
- detail-oriented
- sometimes anxious about getting things right

### Visual treatment

This content should feel:
- trustworthy
- guided
- procedural
- explicit

Preferred traits:
- strong sectioning
- step-based grouping
- clear state feedback
- obvious required/optional logic
- less decorative noise

This family should visually prioritize clarity over atmosphere.

## 6. Review and workflow content

### What it includes

- operator workspace
- operator review queue
- membership review logic
- membership and tracker state handling
- clarification and inclusion decisions

### User mindset

- assessing
- triaging
- deciding
- managing risk and data quality

### Visual treatment

This content should feel:
- controlled
- procedural
- internal
- accountable

Preferred traits:
- denser information handling
- stronger state emphasis
- explicit boundaries between record detail and decisions
- visual distinction between raw input, reviewed state, and downstream outcome

This is where semantic color and state language matter most.

## 7. Status, evidence, and intelligence content

### What it includes

- public signals/dashboard
- company workspace summaries
- wait-time and readiness views
- aggregate trend or bottleneck surfaces
- evidence-linked state summaries

### User mindset

- scanning for patterns
- interpreting progress
- looking for proof or meaning

### Visual treatment

This content should feel:
- analytical
- structured
- interpretable
- evidence-oriented

Preferred traits:
- metric emphasis where real
- simple charts or diagrammatic summaries
- strong labeling of what is aggregate vs private
- visually distinct state chips and readiness language

This family should not be designed like public narrative content, even if it shares the same brand.

## 8. Export and packet content

### What it includes

- registrar/export workspace
- packet state summaries
- inclusion logic
- blockers and versioning

### User mindset

- controlled transmission
- preparing official outward-facing output
- preserving a snapshot

### Visual treatment

This content should feel:
- precise
- versioned
- deliberate
- low-noise

Preferred traits:
- table and summary clarity
- strong version/state labeling
- obvious inclusion/exclusion logic
- less ambient decoration

## 9. Content categories inside Explorer

Within the Explorer specifically, we already have meaningful internal categories that should drive visual treatment:

- crop context
- pest/disease/problem context
- product context
- evidence records
- standards/regulatory content
- resource/guidance content
- registration linkouts

These should not all look identical.

They need a semantic language that can support:
- category recognition
- user expectation
- browse behavior
- cross-linking without confusion

## 10. Proposed semantic visual language directions

This is not yet a final design system. It is a meaning map for later design decisions.

### Public narrative

Signal through:
- larger editorial typography
- broader spacing
- atmospheric surfaces
- lower control density

### Pathway / route selection

Signal through:
- directional cards
- numbered or labeled path cues
- high-clarity CTA structure
- deliberate contrast between options

### Knowledge / library content

Signal through:
- category markers
- clearer content taxonomy
- supportive iconography
- browse-oriented modules

### Forms / applications

Signal through:
- structured steps
- section dividers
- guidance copy
- stable, quiet visual framing

### Internal review / workflow

Signal through:
- operational density
- state emphasis
- records + decisions side by side
- stronger distinction between reviewed and unreviewed material

### Intelligence / dashboards

Signal through:
- metric hierarchy
- compact charts
- summary-to-detail rhythm
- strict public/private labeling

## 11. Semantic color opportunity

Color should not only be decorative. It should help classify meaning.

Likely semantic roles:
- alliance / membership / representation
- registration / workflow / movement
- explorer / knowledge / evidence
- warnings / blockers / clarification
- approved / trusted / ready

This should become a semantic palette, not just a prettier accent set.

## 12. Iconography opportunity

Iconography is especially valuable in 3 areas:

- route selection
- Explorer content taxonomy
- workflow/state signaling

It should help with:
- content recognition
- category memory
- wayfinding
- visual rhythm

It should not become decorative clutter above every heading.

## 13. IA implications

The current ecosystem suggests a layered IA model:

### Layer 1: Public orientation

- Home
- About
- Membership
- Biologicals Explorer
- Track Registrations

### Layer 2: Area landing pages

- Membership landing
- Explorer landing
- Tracker landing
- Workspace gateway

### Layer 3: Deep tools and records

- forms
- dashboards
- product pages
- evidence views
- review views
- export views

The semantic visual language should reinforce this layering.

## 14. What to do next in design terms

Before deeper restyling, the next design decisions should be:

1. Confirm the final set of major content families.
2. Decide the visual tone for each family.
3. Decide how much separation versus resemblance each family should have.
4. Build an asset plan around those families:
   - photography/illustration needs
   - icons
   - diagrams
   - record markers
5. Use that to guide typography, palette, layout rhythm, and eventual design-system extraction later.
