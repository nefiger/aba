# ABA Prototype Consistency Checklist

Last updated: 2026-06-29

Purpose:
- give the prototype a lightweight consistency standard without forcing a full design-system implementation
- make it easier to judge whether a surface is ready to belong in the release snapshot

## 1. Navigation

Check that:
- top-level labels stay consistent across major landing pages
- ordering is stable
- current-page state is clear
- `Workspace` is treated consistently as the deeper role gateway, not an accidental extra link on only one page

## 2. Landing page completeness

Each major landing page should clearly answer:
- what this area is
- who it is for
- what action should happen next
- how it connects back to the wider ABA system

## 3. Visual and layout consistency

Check that:
- page shell and topbar feel related across major areas
- heading hierarchy is clear
- CTA hierarchy is obvious
- card and panel language feels like one family
- typography and spacing do not drift sharply from one surface to another without intent

## 4. State and workflow consistency

Check that:
- application, review, member, and export states are described consistently
- public vs member vs operator vs export boundaries are clear
- “next action” language is visible where a user would expect it
- the prototype shows believable handoffs, not dead ends

## 5. Prototype-as-spec readiness

Before accepting a surface into the release snapshot, ask:
- does it feel intentional enough to be implementation reference material?
- does it introduce any vocabulary or structure that conflicts with another major surface?
- does it make the wider system clearer rather than more fragmented?
